This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Sedjiwa Portal Task Management — a project/task management tool with a React SPA frontend and a Rust (Connect/gRPC-web) API backend (`backend-rs`); a legacy Bun/GraphQL backend (`backend`) is being retired. Part of the larger Sedjiwa Portal ecosystem (core portal, task management). **Identity is self-contained**: the app has its own local users and phone+password auth and no longer depends on the Sedjiwa OIDC provider (see Auth below).

## Repository Structure

```
task-management/
├── apps/
│   ├── frontend/     # Vite + React 19 + TanStack Router/Query + Connect (gRPC-web) + Jotai + Tailwind
│   ├── backend-rs/   # Rust + Arke (custom ECS) + arke-postgres + connectrpc-axum — the backend the frontend consumes
│   └── backend/      # Bun + Bunsane (legacy ECS/GraphQL backend, being retired)
```

The frontend talks to **`backend-rs`** over Connect (proto-generated clients) at `/api/tasks-rs`. The legacy Bun/GraphQL `backend` still exists during the transition but the frontend no longer uses it (Apollo/GraphQL was removed).

## Commands

### Frontend (`apps/frontend/`)
```bash
cd apps/frontend
bun run dev          # Dev server on :3001 (proxies /api/tasks-rs/ → :3010 backend-rs, /api/core|media|sales/ → their services)
bun run build        # Production build (vite build && tsc) — also regenerates src/routeTree.gen.ts
bun run lint         # ESLint on src/**/*.{ts,tsx}
bun run tsc --noEmit # Type-check only
./node_modules/.bin/buf generate   # Regenerate Connect clients into src/lib/gen/ from ../backend-rs/proto
```

**Note on verification:** the ESLint config is currently misconfigured (its parser rejects `import`/`export` across all files) — treat **`tsc --noEmit` + `vite build`** as the real gates until it's fixed. `vite build` also (re)generates `src/routeTree.gen.ts` from `src/routes/`.

### Backend (`apps/backend/`)
```bash
cd apps/backend
bun run dev          # Dev server on :3000 with --watch
bun run build        # Bundle to dist/
bun run start        # Run production bundle
bun run lint         # ESLint on src/**/*.ts
```

Backend has `bun test` coverage for auth/user pure units (`apps/backend/src/**/*.test.ts`); the frontend has no test framework configured.

**Backend auth env:** `AUTH_JWT_SECRET` (required — signing key for the local JWT) and optional `AUTH_JWT_EXPIRES_IN` (default `7d`).

## Architecture

### Frontend

**Stack:** React 19, **TanStack Router** (file-based) + **TanStack Query**, **Connect** (`@connectrpc/connect` + `-web` + `-query`) over proto-generated clients, **Jotai** for local/UI state, Tailwind CSS, shadcn/ui (Radix primitives). No Apollo/GraphQL, no React Router, no Zustand, no CSS Modules.

**Feature-based layout.** UI + data + state are colocated per domain under `src/features/<domain>/`, mapping 1:1 to the product flows:

```
src/
├── main.tsx              # bootstrap: TransportProvider + QueryClientProvider + RouterProvider
├── routeTree.gen.ts      # GENERATED by @tanstack/router-plugin — never edit by hand
├── routes/               # file-based routes — THIN: parse params + guard + render a feature component
│   ├── __root.tsx        # root: router context { queryClient } + <Toaster/>
│   ├── login.tsx · register.tsx
│   ├── _authed.tsx       # pathless layout: token guard (→ /login?redirect=…) + <AppShell/>
│   └── _authed/          # dashboard, my-tasks, projects/index, projects/$projectId(+ tabs)
├── features/<domain>/    # auth, users, projects, tasks, timeline, members, pages, media,
│   │                     #   labels, comments, notifications, activity, dashboard
│   ├── api/              # connect-query hooks + proto→flat mappers
│   ├── components/       # feature-specific UI
│   ├── atoms/            # Jotai atoms (only when needed)
│   ├── types.ts          # flat FE types (mapped from gen/)
│   └── index.ts          # barrel — cross-feature imports go through here
├── components/
│   ├── ui/               # shadcn/ui primitives (shared)
│   └── shared/           # cross-feature helpers (currently just date-picker-field)
└── lib/
    ├── connect.ts        # Connect transport (baseUrl /api/tasks-rs) + auth interceptor + client() factory
    ├── query.ts          # QueryClient
    ├── gen/*_pb.ts        # GENERATED Connect clients (buf) — one per proto
    └── utils.ts          # cn, getInitials, …
```

**Auth:** Local phone + password against `backend-rs`. The session lives in a Jotai atom `sessionAtom` (`features/auth/atoms/session.ts`, `atomWithStorage('sedjiwa.auth', …)`) holding `{ token, user }`. On import it wires `setTokenGetter()` in `lib/connect.ts` so the transport's auth interceptor reads the JWT hook-free (`getDefaultStore().get(sessionAtom).token`) and sends `Authorization: Bearer …`. Route guarding is in `routes/_authed.tsx` `beforeLoad` (no token → `redirect({ to:'/login', search:{ redirect } })`); admin gates read `isAdminAtom`. Auth RPCs (`useMe`/`useLogin`/`useRegister`/`useLogout`) live in `features/auth/api/hooks.ts`.

**Data flow:** All server data flows through **connect-query** hooks in each feature's `api/`. Reads use `useQuery(Service.method.rpc, input, opts)`; writes use `useMutation(Service.method.rpc, opts)` and invalidate related queries with `createConnectQueryKey({ schema: SomeService, cardinality: 'finite' })`. Server-streaming RPCs (e.g. `StreamNotifications`) are **not** connect-query — open them with the raw client `client(Service).theRpc({}, { signal })` and `for await` the async iterable (see `features/notifications`). Each `api/` also holds proto→flat **mapper** functions; components never touch proto message shapes.

**Connect endpoints** (`src/lib/connect.ts`): the shared `transport` targets `/api/tasks-rs` (backend-rs, proxied in dev). `client(Service)` builds a typed client for any generated service descriptor.

**Client/UI state:** Jotai — feature-local atoms; promote to `lib`/shared only when used across features.

**Path alias:** `@/*` → `./src/*`

**Codegen:** `buf generate` (config `buf.gen.yaml`, `protoc-gen-es`) reads `../backend-rs/proto/*.proto` → `src/lib/gen/*_pb.ts`. Services export as `AuthService`, `ProjectService`, etc. (`GenService<…>`); enums/messages alongside. Regenerate after any proto change.

**Route structure:** file-based under `src/routes/`. Key routes: `/login`, `/register`, `/dashboard`, `/my-tasks`, `/projects`, `/projects/$projectId` (detail shell) + tab children `all-tasks` (default) · `timeline` · `members` · `media` · `pages`. `routeTree.gen.ts` is regenerated on `vite build`/dev by the router plugin.

### Frontend Conventions

#### Styling

- **Tailwind CSS utility classes** everywhere. There are no CSS Modules.
- Use `cn()` from `@/lib/utils` to merge/conditional classes.
- CSS variables for theming: `var(--color-*)`, `var(--spacing-*)`, `var(--radius-*)`, etc.

#### Data Hook Patterns (connect-query)

Data hooks live in each feature's `api/hooks.ts`. The method descriptor is `Service.method.rpc`.

- **Query:**
  ```typescript
  export function useLabels(projectId: string) {
    const result = useQuery(
      LabelService.method.listLabels,
      { projectId },
      { enabled: !!projectId },
    );
    return { ...result, labels: (result.data?.labels ?? []).map(mapLabel) };
  }
  ```
- **Mutation** (invalidate related queries by service-level key):
  ```typescript
  export function useCreateLabel() {
    return useMutation(LabelService.method.createLabel, {
      onSuccess: () =>
        queryClient.invalidateQueries({
          queryKey: createConnectQueryKey({ schema: LabelService, cardinality: "finite" }),
        }),
    });
  }
  ```
- **Server-streaming** (not connect-query): `client(Service).theRpc({}, { signal })` + `for await`; ignore `ConnectError` with `Code.Canceled` on unmount (see `features/notifications/api/hooks.ts`).
- TanStack Query exposes `isLoading`/`isPending`/`data`; map `data` → flat types in the hook so components stay proto-free.

#### Feature `api/` File Structure

1. Query hooks (`useQuery` connect-query, mapped return)
2. Mutation hooks (`useMutation` + `createConnectQueryKey` invalidation)
3. Mapper functions in a sibling `api/mappers.ts` (proto message → flat FE type)

Flat FE types live in the feature's `types.ts`. Cross-feature imports go through the feature `index.ts` barrel — avoid deep imports.

#### Shared Components & Helpers

| Need | Use | Location |
|------|-----|----------|
| User initials from name | `getInitials(name)` | `src/lib/utils.ts` |
| Merge class names | `cn(...)` | `src/lib/utils.ts` |
| Date picker with calendar | `<DatePickerField>` | `src/components/shared/date-picker-field.tsx` |
| User/member selector | feature components (`AssigneePicker` in `features/tasks`, member pickers in `features/members`) | per feature |
| Label selector | `<LabelCombobox>` | `src/features/labels` |
| shadcn/ui primitives | Button, Dialog, Select, Popover, … | `src/components/ui/` |

#### Notes

- `ApolloClient`/GraphQL are gone — do not reintroduce them. Server access is Connect only.
- Don't hand-edit `src/routeTree.gen.ts` or `src/lib/gen/*_pb.ts` — both are generated.

### Backend

**Stack:** Bun runtime, `bunsane` (custom in-house ECS framework), PostgreSQL.

**Framework pattern:** `bunsane` uses an Entity-Component-System architecture with decorator-driven GraphQL auto-generation:
- **Archetypes** (`src/archetypes/`): Define entity shapes via `@ArcheType` / `@ArcheTypeField` decorators
- **Components** (`src/components/`): Data containers via `@Component` / `@CompData` decorators (e.g., TaskInfo, TaskAssignment)
- **Services** (`src/services/`): Business logic via `@GraphQLOperation` decorator which auto-generates the GraphQL schema from Zod input schemas and archetype outputs
- **Plugins** (`src/plugins/`): Middleware. `AuthPlugin.extractUser` verifies the locally-issued JWT (HS256, `AUTH_JWT_SECRET`) and returns an `AuthUser` onto the GraphQL context — no OIDC/JWKS.

**Auth & Users:** `src/auth/` is a self-contained module (`types` `AuthUser`/`AuthContext`, `jwt` sign/verify, `permissions` `hasPermission` + `TasksResources`/`TASKS_PERMISSIONS`, `guards` `requireUser`/`requirePermission`/`requireAdmin`) that replaces the former `@qyubit/sedjiwa-permissions` package. User identity lives in `src/components/UserComponents.ts` (Phone/Password/Profile/Status + `UserTag`/`AdminTag`); `AuthService` (register/login/me) and `UserService` (directory + admin CRUD) expose the GraphQL API. The auth-user identity key is `user.id` (admins carry `permissions: ["*"]`). Seed local users with `bun scripts/seed-users.ts` (idempotent). Pure units have `bun test` coverage (`src/auth/*.test.ts`, `src/lib/user-serializer.test.ts`).

**Path alias:** `~/*` → `./src/*`

**Key:** TypeScript decorators are required (`experimentalDecorators` + `emitDecoratorMetadata` + `reflect-metadata`).

**Entry point:** `src/index.ts` → `src/App.ts` (TasksAPI extends bunsane App, registers all services/plugins).

## External Dependencies

- **PostgreSQL** on localhost:5432 (db: `sedjiwa_tasks`)
- **S3-compatible storage** (RustFS) on localhost:9000 (bucket: `tasks-media`) for file uploads
- **Core Portal API** on localhost:3200 for leads/project data

Authentication is handled **locally** (no external OIDC provider). Note: cross-service calls to Core/Media/Sales still send the local JWT, which those services do not yet verify — that integration is handled separately.
