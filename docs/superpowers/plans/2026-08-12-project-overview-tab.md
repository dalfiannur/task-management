# Project Overview Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an Overview tab to the project detail shell — the first tab and the default landing route — showing task statistics, per-module progress, a project info panel, and recent activity.

**Architecture:** One new backend RPC, `DashboardService.GetProjectOverview`, aggregates every count for a single project in one round-trip, applying exactly the same counting rules as `GetDashboardStats` so the dashboard and the tab can never disagree. The frontend gets a new `features/overview/` feature that consumes it; the project record itself (`useProject`) and the activity feed (`<ProjectActivity/>`) are reused rather than duplicated into the new message.

**Tech Stack:** Rust + axum + connectrpc-axum + Arke/`persistence::Store` (backend); React 19 + TanStack Router + connect-query + Tailwind (frontend); protobuf via `connectrpc_axum_build` (Rust) and `buf generate` (TS).

**Spec:** `docs/superpowers/specs/2026-08-12-project-overview-tab-flow-design.md`

## Orientation

Read before starting. These are the facts the tasks below depend on.

**Backend layout** (`apps/backend-rs/`):
- Protos live in `proto/`, compiled by `crates/transport/build.rs`. `dashboard.proto` is already in that list — adding messages/RPCs to it needs no build.rs change.
- `crates/transport/src/dashboard/` holds `mod.rs` (shared `StoreExt`, `internal`, `require_auth`), `context.rs` (cross-project aggregation context + `today()`), `dashboard_service.rs`, `mytasks_service.rs`.
- Record loaders are `pub(crate)` functions in per-domain `record.rs` files. `projects::record` and `work::record`/`work::task_record` are already `pub(crate) mod`; **`pages::record` and `media::record` are still private `mod record;`** and must be widened in Task 3.
- Integration tests live in `crates/transport/tests/`. They skip themselves when `DATABASE_URL` is unset, and drive the router over HTTP JSON with `tower::ServiceExt::oneshot` — so a test can be written *before* the proto exists and will fail with a 404 (missing route).

**Frontend layout** (`apps/frontend/`):
- Generated Connect clients: `src/lib/gen/*_pb.ts`, produced by `./node_modules/.bin/buf generate`. Never hand-edited.
- Features are self-contained folders under `src/features/<domain>/` with `api/hooks.ts`, `api/mappers.ts`, `types.ts`, `components/`, `index.ts`. Cross-feature imports go through the barrel.
- There is **no frontend test framework** in this repo. The gates are `bun run tsc --noEmit`, `bun run lint`, and `bun run build`, plus a manual smoke pass in the running app. Do not invent a test runner; do not skip the manual pass.
- `src/routeTree.gen.ts` is generated by the router plugin on `bun run dev` / `bun run build`. Never hand-edited.

**Running the backend tests:**

```bash
cd apps/backend-rs
set -a; source .env; set +a   # bash/zsh. In fish: `export DATABASE_URL=(grep '^DATABASE_URL' .env | cut -d= -f2-)`

```

If `DATABASE_URL` is not exported the test prints `skip: DATABASE_URL not set` and passes vacuously — that is **not** a green run. Every "Expected: PASS" below means the assertions actually executed.

```rust
//! DashboardService::GetProjectOverview — single-project read aggregation for
//! the Overview tab. Member-gated like ProjectService::GetProject.
//!
//! The counting rules are deliberately identical to `GetDashboardStats`
//! (cancelled excluded everywhere; overdue = past due and not done) so the
//! dashboard and the project tab can never show different numbers.

use std::collections::{HashMap, HashSet};

use auth::AuthUser;
use axum::Extension;
use connectrpc_axum::{ConnectError, ConnectRequest, ConnectResponse};
use domain::task::TaskStatus;

use super::context::today;
use super::{internal, require_auth, StoreExt};
use crate::media::record::ready_media_for_project;
use crate::pages::record::pages_for_project;
use crate::projects::parse_pid;
use crate::projects::record::{is_member, load_project, project_member_ids};
use crate::sedjiwa::tasks::dashboard::v1 as pb;
use crate::work::record::modules_for_project;
use crate::work::task_record::tasks_for_modules;

pub(super) async fn get_project_overview(
    Extension(store): StoreExt,
    user: Option<Extension<AuthUser>>,
    req: ConnectRequest<pb::GetProjectOverviewRequest>,
) -> Result<ConnectResponse<pb::ProjectOverview>, ConnectError> {
    let auth = require_auth(user)?;
    let ConnectRequest(r) = req;
    let pid = parse_pid(r.project_id.trim())?;
    let project = load_project(&store, pid)
        .await
        .map_err(internal)?
        .ok_or_else(|| ConnectError::new_not_found("project not found"))?;
    let project_id = pid.to_string();
    if !auth.is_admin()
        && !is_member(&store, &project_id, &auth.id)
            .await
            .map_err(internal)?
    {
        return Err(ConnectError::new_permission_denied("not a member"));
    }

    // Modules come back sorted by (order, pid); one task query covers them all.
    let modules = modules_for_project(&store, &project_id)
        .await
        .map_err(internal)?;
    let module_ids: HashSet<String> = modules.iter().map(|m| m.pid.to_string()).collect();
    let tasks = tasks_for_modules(&store, module_ids)
        .await
        .map_err(internal)?;
    let today = today();

    let mut total = 0u32;
    let mut in_progress = 0u32;
    let mut done = 0u32;
    let mut overdue = 0u32;
    // module_id → (done, total)
    let mut per: HashMap<String, (u32, u32)> = HashMap::new();

    for t in &tasks {
        if t.status == TaskStatus::Cancelled {
            continue; // cancelled counts nowhere
        }
        total += 1;
        match t.status {
            TaskStatus::InProgress => in_progress += 1,
            TaskStatus::Done => done += 1,
            _ => {}
        }
        if let Some(due) = &t.due_date {
            if due.as_str() < today.as_str() && t.status != TaskStatus::Done {
                overdue += 1;
            }
        }
        let e = per.entry(t.module_id.clone()).or_insert((0, 0));
        e.1 += 1;
        if t.status == TaskStatus::Done {
            e.0 += 1;
        }
    }

    // Driven off `modules`, not off `per`: a module with no tasks must still
    // appear (as 0/0), and the module order is the one the Tasks tab shows.
    let per_module: Vec<pb::ModuleProgress> = modules
        .iter()
        .map(|m| {
            let (d, tot) = per.get(&m.pid.to_string()).copied().unwrap_or((0, 0));
            pb::ModuleProgress {
                module_id: m.pid.to_string(),
                module_name: m.name.clone(),
                done: d,
                total: tot,
            }
        })
        .collect();

    // Owner first; the helper already returns the rest sorted and deduped.
    let mut member_ids = project_member_ids(&store, &project_id)
        .await
        .map_err(internal)?;
    if let Some(i) = member_ids.iter().position(|u| u == &project.owner_id) {
        let owner = member_ids.remove(i);
        member_ids.insert(0, owner);
    }

    let page_count = pages_for_project(&store, &project_id)
        .await
        .map_err(internal)?
        .len() as u32;
    let media_count = ready_media_for_project(&store, &project_id)
        .await
        .map_err(internal)?
        .len() as u32;

    Ok(ConnectResponse::new(pb::ProjectOverview {
        total_tasks: total,
        in_progress_tasks: in_progress,
        done_tasks: done,
        overdue_tasks: overdue,
        per_module,
        member_ids,
        module_count: modules.len() as u32,
        page_count,
        media_count,
    }))
}
```
